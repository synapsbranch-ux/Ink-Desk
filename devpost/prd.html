Ink Desk

Product requirements. You pitch a story; Ink Desk turns it into a real 4-panel manga page with your own characters drawn consistently across every panel.

Approved 4 stations · 1 page · 2 characters Canonical: prd.md

Screens and layout

The station rail: gates and back doors

The rail is both a progress indicator and navigation. A station is clickable only once its prerequisite is met — so the dependency chain teaches itself instead of erroring.

The kernel, sharpened

Why DNA comes first

The original ordering drew the sheet, then wrote the DNA from the description. That let the two locked artifacts contradict each other — and a contradiction gets sent to the image model on every panel. Reversing the order removes the possibility.

Locking is final in this version. Claude checking the image against the DNA automatically was judged a nice Later — the human does that check here.

The core journey

Thirteen steps, end to end

  1. Arrive at Story. Pitch box, genre and tone chips, a “Try the sample” link. Four stations visibly locked.
  2. Pitch — type an idea (or seed it with the sample) and pick a genre and tone.
  3. Read the synopsis. Editable field. Rewrite, regenerate, or accept.
  4. Accepting unlocks Cast. Claude proposes two characters — name, role, traits, look description.
  5. Shape the cast. Edit freely; Reroll a character. Text only, so it's cheap.
  6. Draw a sheet. Claude writes the DNA, then the sheet image is generated from it.
  7. Check picture against words. DNA shown beside the art. Redraw reuses the same DNA.
  8. Lock. The stamp lands. The pair is frozen and final.
  9. Both sheets locked unlocks Storyboard. Claude writes the 4-panel script, one locked character per panel.
  10. The page inks in. Four background generations, filling in as they land, each playing the reveal on arrival.
  11. Fix what missed. Compare each face to its sheet; Redraw keeps the last three versions.
  12. All four panels have art, unlocking Ink & Publish. Full-page read, the reveal replaying panel by panel, right-to-left toggle, PNG export.
  13. Success: each character is recognizably themselves in every panel they appear in — Kaito in 1 and 3, Mio in 2 and 4.

Features and behavior

Station by station, with the checks

Each panel lists what the station does and the criteria you can verify by looking at the screen during the build.

Always available

Story — the pitch desk

Write a pitch, pick a genre and a tone, read Claude's synopsis, edit or regenerate it, accept it.

Try the sample
Fills the pitch text only — the Kaito rooftop-courier pitch. Everything after is generated for real.
The synopsis
Lands in an editable field — “editable, never final.”
Gate
Accepting the synopsis unlocks Cast.

Acceptance criteria

  • Typing a pitch and submitting returns a synopsis with a title and body
  • The synopsis text can be edited in place
  • “Try the sample” populates the pitch box and nothing else
  • Cast is unclickable before acceptance, and shows a hint on hover
  • Accepting a synopsis makes Cast clickable
Assumption: genre and tone chips reuse the mockup's sets — genres Shonen, Romance, Horror, Slice of Life; tones Hopeful, Fast-paced, Melancholy, Comedic, Eerie. Trivial to change.
Unlocks when a synopsis is accepted

Cast — model sheets

This is where the kernel is built. Claude proposes, the user edits, then locks. Nothing about a character is final until the user has approved both the words and the picture.

Claude proposes
Two characters: name, role, personality traits, short look description.
User edits
All text editable. Reroll replaces one character. Text only, cheap to iterate.
Draw sheet
Claude writes the DNA → the sheet is generated from that DNA. One image, laid out as a real model sheet. Never cropped into frames.
Lock
Freezes the approved DNA/image pair. Final — no unlock in this version.

Sheets have no version history: a sheet is only final once locked, so there is nothing to revert to.

Acceptance criteria

  • Accepting a synopsis produces two character proposals with name, role, traits, and look description
  • All proposed text is editable
  • Reroll replaces exactly one character and leaves the other untouched
  • Draw sheet produces one image and displays DNA text next to it
  • Redraw sheet produces a different image from the same visible DNA text
  • Editing the description and redrawing changes the DNA text on screen
  • Locking shows the Locked stamp and makes the card read-only
  • Storyboard is unclickable until both characters are locked
Runs when both sheets are locked

Page script — the breakdown

Claude writes the script for all four panels: which character, the action, the camera angle, the background, and the dialogue.

Hard constraint
Exactly one locked character per panel — what keeps every image request single-reference.
Role in the prompt
The script is the variable part; sheet, DNA and style rules are frozen.
Order
Shot/reverse-shot. For the sample: Kaito → Mio → Kaito close-up → Mio reacting.
Dialogue
Not editable in this version — line-by-line editing is the deferred Script Strip.

Acceptance criteria

  • The script names one character per panel, and no panel names two
  • Each panel has an action, a camera angle, a background, and dialogue
  • Characters alternate across the four panels
Unlocks when both sheets are locked

Storyboard — the main studio

Four panels generate in the background, each request carrying only that panel's sheet and DNA, plus fixed style rules and an instruction that the image contain no text.

Per-panel independence is the governing rule. Own status, own placeholder, own reveal, own failure, own versions. Panels fill in as they finish — not necessarily in order.

Version stepper
Appears once a panel has two versions: first redraw reads ‹ 2 / 2 ›, second ‹ 3 / 3 ›. Never above three — the oldest drops off.
Redraw in progress
The current art stays visible with a small “Inking…” indicator, and Ink & Publish stays open. A failed redraw leaves the previous version up. A panel is never left empty.
The displayed version counts
It's what appears on the page, in the reader, and in the PNG.
Lettering
Bubbles overlaid by the app in Comic Neue — never drawn by the image model.
Gate
Ink & Publish stays locked until all four panels have art.

Acceptance criteria

  • All four panels show pencil placeholders with per-panel labels before art arrives
  • A panel that finishes first displays its art while others are still generating
  • Each panel plays the ink-in reveal as it lands
  • Every panel prompt asks for no text; if a panel comes back with text in it, Redraw is the fix
  • Speech bubbles appear over the art in Comic Neue with Claude's dialogue
  • Redrawing one panel leaves the other three untouched
  • One redraw makes a ‹ 2 / 2 › stepper appear; a second makes it ‹ 3 / 3 ›
  • Further redraws never push the stepper above 3
  • During a redraw the panel keeps showing its current art with an “Inking…” indicator
  • A failed redraw leaves the previous version on screen, not an empty frame
  • Ink & Publish stays clickable while a panel is being redrawn
  • Ink & Publish is unclickable until all four panels have art, with a hint such as “Finish panel 3 first”
Unlocks when all four panels have art

Ink & Publish — the reader

Full-page reading, with the ink-in reveal replaying panel by panel on entry. This is the shot that gets filmed.

Right-to-left toggle
Manga reading order. Kept because it's cheap and it's very manga.
PNG export
Composites the panel images and the overlaid bubbles into one file.
Round trip
Back to Storyboard, redraw, return — the reader shows the new art.

Acceptance criteria

  • Entering the station replays the ink-in reveal panel by panel
  • The right-to-left toggle visibly changes panel reading order
  • Exported PNG contains both the art and the speech bubbles
  • The exported page uses each panel's currently displayed version
  • Returning to Storyboard, redrawing a panel, and coming back shows the new art

States and boundaries

Waiting, failing, and coming back

Generating

Per-panel, independent, out of order.

Inking panel 2…

Dotted silhouette in halftone style, subtle shimmer, per-panel label. Each panel plays its reveal as it lands.

Rate limit or timeout

The app quietly retries once. If that fails too:

Panel 3 didn’t come back,
the studio is busy.
Try again

Other panels unaffected. A waiting problem gets a wait button.

Refusal

The image model won't draw it as written.

This panel couldn’t be drawn as written.
Rewrite panel

Claude rephrases only the visual description — action, angle, background — and retries. The dialogue stays the same. A wording problem gets a rewrite button.

Persistence

One chapter, same browser. Confirmed by the “Saved to desk” label, beside a small “Images this chapter: 8” counter — awareness only, no hard cap.

Restores the synopsis, cast proposals, locked sheets with their DNA, page script, panels and their version history, and the current station. Closing the tab and returning tomorrow brings the same chapter back.

Reload mid-generation

Generation survives the reload. Panels are generated server-side, so a reload shows each in-flight panel either finished or still inking — and it keeps going.

Safety net: a panel still inking after a generation timeout, or after the server restarted, falls back to the failed state with “Try again.” The dev server kills in-flight requests on every code change, so “keeps generating” needs a floor. Nothing spins forever; nothing finished is lost.

“A stray refresh during the demo never costs me six generations.”

Changed in 4-spec from the approved version, which failed in-flight panels outright.

Starting over

New chapter — explicit action, with a confirmation, clears everything.

Accepting a new synopsis from Story does the same, warning that the cast and page will be cleared.

No accounts. No saved-chapter list. One chapter at a time.

Two invariants that hold everywhere: no raw error codes on screen, ever — and a failure never wipes panels that already succeeded.

Product decisions

Choices, with their reasons

  • Guided, with free back-navigation and a prerequisite-gated rail. The dependency chain is real, so gating teaches it; hover hints explain rather than error.
  • Claude proposes the cast; the user edits and locks. “The studio does the work, but the user keeps authorship.” Text iteration is cheap, so Reroll is free to use.
  • DNA first — the DNA is the sheet prompt. So the two locked artifacts cannot contradict each other. “The picture is the DNA made visible by construction.”
  • Locking is final; no unlock. Keeps the contract simple and the build small.
  • “Try the sample” fills the pitch text only. Seeds the demo without faking any generation.
  • Retry once silently, then ask. One quiet retry absorbs ordinary flakiness without making the user watch a spinner twice.
  • Retry and Rewrite as distinct repairs. Transient failures and refusals have different causes, so they get different buttons.
  • Three versions per panel. Enough to compare and revert, few enough to stay simple.
  • One chapter persists; no chapter library. Protects the demo against a stray refresh without building an account system.
  • Panels fill out of order. One slow request shouldn't hold the other three hostage.
  • A redraw never blanks a panel. The current art stays up while redrawing, and stays up if the redraw fails, so the page is never less finished than it was.
  • Rewrite only touches the visuals. Dialogue is untouched, consistent with dialogue editing being deferred.
  • A visible image counter, but no hard cap in the product. Awareness beats enforcement at this size.

The boundary

Building, deferred, never

Building The complete proof of concept 8 items
  • Story — pitch box, genre and tone chips, “Try the sample”, Claude synopsis, editable, acceptable.
  • Cast — two proposed characters, editable text, per-character Reroll, Draw sheet (DNA then image), DNA shown beside art, Redraw sheet, Lock with stamp.
  • Page script — four-panel breakdown, one locked character per panel.
  • Storyboard — four background generations, pencil placeholders, per-panel status, ink-in on arrival, overlaid Comic Neue bubbles, Redraw panel, three-deep version stepper.
  • Ink & Publish — full-page reveal, right-to-left toggle, PNG export compositing art and bubbles.
  • Station rail — prerequisite gating, hover hints, the three back-navigation rules.
  • Failure handling — silent single retry, Try again, Rewrite panel, plain language only.
  • One-chapter persistence — “Saved to desk”, restore including versions and station, in-flight panels that keep generating across a reload with a timeout/restart fallback to the failed state, New chapter with confirmation.
Deferred Implied, but not now 10 items
  • A panel with both characters together — needs multi-reference generation.
  • Director's Chair chat for directing Claude on a selected panel.
  • Script Strip — line-by-line dialogue editing. Dialogue is display-only here.
  • Backgrounds and scenes shelf as reusable generated assets.
  • Unlocking a locked sheet — why back-to-Cast is view-only.
  • Claude auto-checking the sheet against the DNA — the human does this check.
  • Multiple page layouts. The mockup has three; this builds one.
  • Accounts and a saved-chapter library.
  • PDF export and share link. PNG only.
  • Deployment — optional for this hackathon.
Non-goals Will tempt during the build 7 items
  • Real two-pass pencil→ink generation The ink-in is a reveal over the finished image. One generation per panel, always.
  • Five-frame model sheets One image, or there's no single canonical reference to send.
  • Manual panel touch-up or painting The only repairs are Redraw and Rewrite. If a redraw is still off, accept the best one — “an honest proof of concept, not a guarantee.”
  • A third character Two prove the lock isn't a fluke.
  • Text rendered by the image model Every panel prompt asks for no text; all lettering is overlay.
  • Reusing the mockup's code Visual reference only.
  • Raw error codes or stack traces on screen Plain language, always.

Open questions

What's still unsettled

Does not block 4-spec

  • Does the page script get its own rail entry, or live inside Storyboard? Drafted as inside. Cosmetic and reversible.
  • Should the genre and tone chip sets stay exactly as the mockup has them? Assumed yes.
  • How long the reader's ink-in reveal should run versus the mockup's ~1.4s per panel. A four-panel sequential reveal may want faster per-panel timing to stay watchable. Tune during build.

Does block — answer in 4-spec

  • Which GPT Image model and endpoint accept reference images, and how many per request. The entire kernel rests on it. Carried from scope.md. Verify before building Cast.
  • Panel generation concurrency. Preference going in: a small limit, around two at a time, so panels still fill out of order without firing four requests at once. Firing all four is the likeliest way to trip a rate limit — which would put the failure state on camera.
  • A server-side safety limit on images per chapter. The product counts; it does not cap.

From one page to a planned chapter

Two surfaces, one rail

SurfaceRouteHolds
Dashboard/project cards · New project · global library · budget readout
Studio/p/<project>the rail for one project: Story (pitch or scenario) → Library → Director → Page → Ink & Publish

Gates as in v1: Library opens on an accepted synopsis or a saved scenario; the Director on two locked characters; Page on a plan; Ink & Publish on the first page with four inked panels. The header shows the open page and "Images this project: N · ≈ $X".

The journey, eleven steps

  1. Arrive at the dashboard. Cards, New project, the global library, the budget. A v1 desk appears as one project.
  2. New project: title + a style preset (at least Manga B&W and Manhwa colour), locked with the project.
  3. Tell the story: the v1 pitch, or Scenario mode — a long text with notes and references.
  4. Build the library: Draw sheet (DNA then picture) or Import reference — the upload becomes the sheet and Claude writes the DNA from the picture. Same Lock.
  5. The Director writes a plan: ≥ 3 pages of the v1 four-shot page, plus a cover brief, with the cost estimate before any image.
  6. Edit the plan — any line, the page count (3–6), the cover brief.
  7. Generate page by page, or all; the cover is one image with the title lettered by the app.
  8. Fix what missed — bubbles, Redraw, versions, Try again, Rewrite, per panel, per page.
  9. Read the chapter — cover first; right-to-left for manga, vertical scroll for manhwa.
  10. Export — PNG of any page, PDF of the chapter.
  11. Success: the imported character's upload beside their panels on pages 1–3 and the cover; every locked character recognizably themselves on every page.

Station by station — the checks

Dashboard · New project · presets
  • A fresh install shows an empty dashboard; a v1 desk migrates into one card with its page and images intact.
  • A card shows the cover, else the first inked page, else a placeholder; the global library is read-only.
  • New project asks for a title and a preset, nothing else; the preset is locked and shown on the card and rail.
  • Every sheet, panel and cover request carries the preset's rules verbatim; presets never name a real work or artist.
Scenario mode · assets · Library
  • Pitch or Scenario; a saved scenario unlocks the Library like an accepted synopsis; long text is summarized first and says so.
  • Uploads (PNG, JPEG, WebP, size cap) appear on a shelf, with a rights notice.
  • Import reference sets the sheet and writes the DNA from the picture; Lock still needs both; a locked imported character sends the imported bytes as the single reference; Redraw sheet is unavailable on an import.
The Director · pages · cover
  • A plan of ≥ 3 pages and a cover brief from the story, cast and style; one locked character per slot, alternating, by schema.
  • Thumbnails, every line editable, page count adjustable; the cost estimate shown before generation and labelled an estimate.
  • Generate page / Generate all, both idempotent; a page's failure never touches another; per-panel repair on any page.
  • The cover: one image with the locked characters in the project's style; the title lettered by the app, editable, never requested from the model.
  • A page switcher; "N of 4 panels inked" per page and "P of Q pages complete" per chapter.
Reader · export
  • Ink & Publish unlocks on the first complete page; cover first, then complete pages in order; incomplete pages as placeholders.
  • Manga: right-to-left with the toggle. Manhwa: one vertical scroll. The ink-in replay per page.
  • PNG per page; PDF of the chapter — cover + pages at page size, bubbles and lettering composited, current versions; both in the browser.

States and boundaries (v2)

  • Projects persist in data/projects/<id>/ (local mode); the v1 file migrates once and is left untouched.
  • Storage modes: INKDESK_STORAGE=local (default; a clone runs with no account) or cloud (MongoDB + an S3-compatible bucket). The demo runs local.
  • Text fallback: no Anthropic key, a 402, or a server error past the single retry → openai/gpt-5.6-terra via OpenRouter, same schemas; the terminal names the provider, the screen does not change.
  • Budget is informational, no hard cap; the Director's estimate makes spending a decision.
  • Feature freeze 2026-10-20. After it: fixes, the video, the README.

Deferred and never

Deferred: in-app video export and dubbing (only if items 1–9 are done by Oct 20 — otherwise Later, no debate); two characters in one panel; volumes in the UI; alternative image models unless one passes the kernel test before Oct 18; style and setting locks beyond candidates; accounts, deployment, the mini-game, a shared library. Never: claiming a candidate lock before its test; a second layout; a hard cap; any feature not on the list after Oct 20.

Open: the page-count range (drafted 3–6); a tall-strip export for manhwa; reusing a locked character across projects; which premade voice narrates the video.
