Ink Desk

An AI manga creator studio: you pitch a story idea, and the app turns it into a real manga page with your own characters drawn consistently across every panel.

Approved Proof of concept 2–4 hours active Canonical: scope.md

The unique kernel

Locked appearance, free action

Locked

The app can change what a character does in a panel — never what they look like.

Each character gets a model sheet generated once, then frozen. Locking freezes two things, and both travel with every single panel request:

1 · Visual reference
The sheet image itself, sent to the image model — “so the face, hair and outfit come from a picture and not just from words.”
2 · Visual DNA
Text Claude writes once at character creation — hair, eyes, face shape, outfit, colors, one or two distinguishing marks. Pasted word for word into every panel prompt, never rewritten.

Why this is the kernel: most AI comic tools change the hero’s face in every panel. Delete this and Ink Desk is a generic prompt-to-image toy.

Station 2 · Cast — model sheets

This is where the kernel is built. Two characters. Each gets DNA text from Claude and one single image laid out as a real model sheet — front, three-quarter and a few expressions in one frame. That one image is the canonical reference. No cropping it into separate frames.

You do

GPT Image draws
One sheet image per character — 2 generations.
Locks
Sheet image + DNA text. Unlocking and editing a sheet is out of scope.

Station 3 · Page script — the breakdown

Once the synopsis is accepted, Claude writes the script for all four panels. This step is load-bearing: the script is the variable half of every panel prompt.

Claude Sonnet writes
Per panel: which character, the action, the camera angle, the background, and the dialogue.
Hard constraint
Exactly one locked character per panel, so each request carries a single reference.
Feeds
The dashed box in the diagram above.

Station 4 · Storyboard — the main studio

Four panels generated against the locks, each prompt carrying only that panel’s character sheet and DNA. Panels generate in the background with visible per-panel progress.

GPT Image draws
4 panels — one generation each, never two.
You do

Redraw means
Same request, same references. Keeps the previous version so you can switch back. Never touches other panels.
No manual painting
If a redraw is still off, you accept the best one.

Station 5 · Ink & Publish — the reader

Full-page reading. The pencil-to-ink reveal plays once the page is ready.

Theatrical, not real. A reveal animation over the finished image — same look on camera, half the generations.
Lettering
Bubbles overlaid in Comic Neue, never drawn by the image model.
Controls
Right-to-left toggle (kept — it’s a CSS flip and very manga for the cost).

What “working” looks like

The money shot

Success criterion

Each character is recognizably themselves in every panel they appear in.

Stated per-character on purpose: shot/reverse-shot means no one appears in all four panels. Kaito is in 1 and 3, Mio in 2 and 4. The claim is continuity across their panels — not one face across the whole page.

The boundary

Now, later, cut

Nothing disappears silently. Open each to see what’s inside and why.

Now In the proof of concept 5 stations
  • Story — pitch box, genre and tone, editable Claude synopsis.
  • Cast — two characters, each with DNA text and one single sheet image, locked.
  • Page script — Claude’s 4-panel breakdown, one locked character per panel.
  • Storyboard — 4 panels generated against the locks, per-panel Redraw with version switching, dialogue overlaid as bubbles in Comic Neue.
  • Ink & Publish — full-page read, pencil-to-ink reveal, right-to-left toggle, PNG export compositing image and bubbles.

Three deliberate risk cuts

  • The ink-in effect is theatrical. One generation per panel; the transition is a reveal animation. Same look on camera, no second consistency risk.
  • One reference image per request. Single-character panels mean the app never sends two sheets at once.
  • No text in generated images. Lettering is app-side overlay, so the image model is never asked to render type.

Budget: roughly 2 sheets + 4 panels = 6 images per full run, plus redraws.

Later Worth doing, just not now 9 items
  • A panel with both characters together — needs multi-reference generation. The main reason it’s deferred.
  • Director’s Chair chat for directing Claude on a selected panel.
  • Script Strip for editing dialogue line by line.
  • Backgrounds and scenes shelf as separately generated, reusable assets. For now, background folds into the panel prompt.
  • Multiple page layouts — the mockup has three (5-panel, 3-panel splash, 4-panel with an SFX insert).
  • PDF export; share link.
  • Unlocking and editing a sheet after it’s locked.
  • External comic APIs such as LlamaGen.
  • Deployment — optional for this hackathon.
Cut Named, with reasons 5 items
  • Real two-pass pencil→ink generation Doubles image cost and adds a second chance for the face to drift, for an effect on screen for ~1.4 seconds. A CSS reveal is indistinguishable on camera.
  • Five-frame model sheets Separate front / three-quarter / expression images cost five times as much, drift five ways, and leave no single canonical reference to send. One sheet image solves all three.
  • Manual panel touch-up or painting The only repair is Redraw. Keeps the loop honest and the build small.
  • A third character The mockup’s Old Tetsu. Two characters prove the lock isn’t a fluke; a third adds cost without adding proof.
  • Reusing the mockup’s code It’s a design reference, and it fakes all art with CSS. The styling language carries over; the implementation does not.

Carried forward

Open questions, by owner

Verify in 4-spec

  • Which GPT Image model and endpoint accept reference images, and how many per request. The whole kernel rests on this. Verify before building Cast — it’s the one assumption that could force a redesign.
  • Image cost and rate limits at ~6 images per run plus redraws.

Resolve in 3-prd

  • What the user sees while panels generate — per-panel progress, partial page reveal.
  • Hard failure handling — not “the face is wrong,” but 429s, timeouts, refusals, malformed responses.

Latency direction already set: panels generate in the background with visible per-panel progress; the reveal plays once the page is ready. The demo video may trim the waiting, but the generation itself has to be real — no pre-baked images.

Revision · 2026-10-13 · decided by the learner

Ink Desk Studio (v2) — from one page to a chapter

After the v1 final review the learner's verdict was: "not really an AI manga creator with chapters and volumes — much more a single storyboard creator." v1 is complete and tagged v1-poc; it stays the fallback submission. v2 is the smallest studio that makes a three-minute video prove manga creator, with a feature freeze on 2026-10-20 and a cut line written in advance.

The kernel, restated: one contract on three things

Locked appearance, free action — for the character, the style, and the setting.

The app can change what happens in a panel, never how the character, the art style or a locked place looks. The character lock is the anchor and the only one proven. Style and setting are candidate locks until each passes its own kernel test (one reference image, three panels at medium); until then the video does not claim them. An imported reference is just another way to create a lock: the learner's image replaces the generated sheet, same contract.

The v2 loop

What "working" looks like now

One character, one chapter, several pages. The imported character's reference image beside panels from page 1, page 2 and page 3 plus the cover — close-up, medium, wide — same face, same outfit, same marks. Success: each locked character is recognizably themselves in every panel they appear in, across every page and on the cover; an imported character recognizably matches the upload. A second style as a short showcase is optional and not a criterion.

Now, later, cut — v2

Now — on screen on Oct 26 (feature freeze Oct 20)
  1. Dashboard: project gallery with covers, New project, global library, budget.
  2. New project: title + a locked style from presets — at least manga B&W and manhwa colour.
  3. Full scenario mode: paste a long scenario, with references.
  4. Library: two locked characters, one imported from the learner's own image, one drawn from DNA + sheet.

  6. Generation: the 5b states, editable bubbles, the slice 6 repair logic — per page.
  7. Reader: the whole chapter; right-to-left for manga, vertical scroll for manhwa.
  8. Export: PNG per page + PDF of the chapter.
  9. Storage behind an interface: local by default; MongoDB + bucket switchable; the demo runs local.
  10. Text fallback to openai/gpt-5.6-terra — in the code and README, not on screen.
Later — explicitly out of the submission
  • In-app video export with camera motion and in-app ElevenLabs dubbing — only if 1–9 are done by Oct 20; "otherwise Later, no debate."
  • Two characters in one panel (needs a kernel test). Multiple volumes in the UI.
  • Alternative image models in the app unless one passes the kernel test before Oct 18.
  • Style and setting as reference-image locks past the candidate stage. Accounts, deployment, the mini-game, a shared library.
Cut — never in v2
  • Claiming a candidate lock in the video before its test.
  • A second page layout; three or more locked characters in the demo.
  • Shipping Mongo as a requirement; any feature not on the list after Oct 20.

Providers (v2) — verified 2026-10-13

  • Text: Anthropic claude-sonnet-5-5 first; fallback openai/gpt-5.6-terra through OpenRouter chat completions with strict JSON schema, the same zod schemas validating the reply.
  • Images: OpenRouter openai/gpt-image-2.5-sunburst (proven); other models are candidates behind a kernel test.
  • Demo narration: ElevenLabs through OpenRouter, POST /api/v1/audio/speech, elevenlabs/eleven-v4 — ≈ $0.04 per 1 000 characters.
  • Storage: local files (default) · MongoDB + an S3-compatible bucket (INKDESK_STORAGE=cloud).
