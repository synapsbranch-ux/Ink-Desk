Ink Desk · app map · proof of concept v1

Where things live

A snapshot of the finished proof of concept at commit 5329b8a (2026-10-13): what the app is, how one action travels through the code, where to start a change, and one practice from this build worth reusing. Code moves; this page does not. If a path here is wrong, the code is right.

What this is, in four pieces

Ink Desk turns a story pitch into a real four-panel manga page, with two characters who stay recognisably themselves in every panel they appear in. One Next.js app, nothing else running:

PieceWhereWhat it does
The studioapp/page.tsx, components/Four stations in the browser: Story → Cast → Storyboard → Ink & Publish. Shows what exists, lets you act on it. Holds no secrets, generates nothing.
The route handlersapp/api/**/route.tsSmall server functions, one per action. The only code that sees the API keys and talks to the providers.
The deskdata/chapter.json, data/images/One JSON file is the whole chapter; every generated picture is a file beside it. Written only through lib/chapter.ts, one change at a time.
Two providerslib/claude.ts, lib/image-provider.tsClaude writes every word (synopsis, cast, visual DNA, script, dialogue). An image model, reached through OpenRouter, draws every picture.

The kernel — the idea everything else serves: each character gets one model sheet and one short "visual DNA" text, both frozen when you Lock. Every panel request carries that sheet as an attached reference picture plus the DNA word for word. Claude only ever writes the part that changes: action, camera, background. Locked appearance, free action.

One action, followed through

The action worth knowing: both characters are locked, and the page inks in. Here is where each step happens.

A reference route, three stops

Not toured interactively — the learner's hands-on time went into the kernel test and the live checkpoints instead (see the practice below). Open these in order to see the kernel in code.

  1. lib/panels.ts → inkPanel
    The panel job. It claims the panel inside the write lock, reads that character's locked sheet with readImage, and calls generateImage with references: [sheet]. Search for references: to find the one line that makes the face hold.
  2. lib/prompts.ts → panelPrompt, STYLE_RULES, PANEL_LAYOUT
    The frozen half of every request. panelPrompt pastes the DNA word for word, then the slot's framing line from PANEL_LAYOUT, then Claude's variable part, then STYLE_RULES with its "absolutely no text" rule. Nothing about the character is rewritten per panel.
  3. components/Panel.tsx
    The visible result. The <img> points at /api/image/<id>; a never-seen image id plays the ink-in (search is-inking), and SpeechBubble sits on top in Comic Neue. The art never carries lettering; the app draws it.
Where the lock itself is enforced

Clicking Lock in components/CharacterCard.tsx calls onLock; app/page.tsx's lock() commits the patch { cast: { [id]: { locked: true } } } to POST /api/chapter. The server, not the UI, decides: assertEditAllowed in lib/cast.ts refuses a lock without both a DNA and a sheet, and refuses every later edit on a locked card with a 409. npm run check:cast asserts all of it with no provider in the loop.

To change this, start here

You want to…Start at
Change the drawing style (ink, screentone, "no text")lib/prompts.ts → STYLE_RULES. Pasted into every sheet and panel prompt; change it once, it changes everywhere. The copy in scripts/kernel-test.mjs is separate on purpose.
Change a shot (wide / medium / close-up) or which character takes a slotlib/prompts.ts → PANEL_LAYOUT. Each slot carries its shape, stance and framing line; the schema in lib/schemas.ts → pageScriptSchema reads the same slots.
Switch model, quality or aspect ratios.env → IMAGE_MODEL, IMAGE_SHEET_QUALITY, IMAGE_PANEL_QUALITY, IMAGE_*_ASPECT. Read at call time in lib/image-provider.ts → imageConfig().
Run more or fewer panels at once.env → PANEL_CONCURRENCY (the queue in lib/queue.ts, pinned once per process in lib/singleton.ts).
Change where a bubble lands by defaultlib/bubble.ts → defaultBubble, driven by bubbleCorner in lib/script.ts.
Change the "Sketching the pose…" status lineslib/stages.ts → PANEL_STAGES, SHEET_STAGES. Pure; npm run check:stages covers it.
Change the genre and tone chips, or the sample pitchlib/prompts.ts → GENRES, TONES, SAMPLE_PITCH.
Change the exported PNG's sizelib/export.ts → EXPORT_WIDTH; the geometry is pageGeometry, covered by npm run check:export.

A practice to reuse

Prove the riskiest assumption with a throwaway script before building any screen

The whole product rested on one unknown: does a single reference picture plus a frozen text actually hold a face across shots? Rather than find out after five stations were built, slice 1 and slice 2 of devpost/checklist.md ran scripts/kernel-test.mjs first. --probe-only asked the providers what they support, for about a cent; the full run drew one sheet and two panels at medium and wrote data/kernel-test/index.html so the answer was a thing you could look at.

What it caught, from devpost/spec.md and checklist.md › Revisions:

  • The text model rejects thinking: { type: 'disabled' } with a 400; the accepted value is between_tools. Found by the probe, not three stations in.
  • The image endpoint has no size parameter and would have silently dropped it; aspect_ratio is the real knob. A 200 with the wrong shape is the worst kind of bug.
  • Cost is driven by scene density, not aspect ratio — the spec's cost table had the wrong shape, and the probe's real usage.cost replaced it.

Where it helps next time: any project whose value depends on one external behaviour you have not seen with your own eyes — an API's real limits, a model's real output, a library's real performance. Write the smallest script that produces runnable evidence, keep it in the repo, and re-run it before you ship (spec.md › Verified: Image Model and Reference-Image Support asks for exactly that before filming, as the canary for model drift).

Its companion: acceptance checks with the provider stubbed

Every station has a script under scripts/*-check.mts that replaces fetch and asserts the rules against a scratch folder: check:page proves every panel request carries exactly one reference and never the dialogue; check:repair proves one silent retry on a 429 or timeout and never on a 402; check:store proves two same-tick writes both land. They cost nothing and run in seconds, so the rules stay true while the code around them changes.
