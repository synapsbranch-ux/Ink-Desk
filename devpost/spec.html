Ink Desk

One Next.js app, two AI providers called from the server, one chapter of work kept on disk.

Next.js · App Router claude-sonnet-5-5 openai/gpt-image-2.5-sunburst via OpenRouter Local only

The verification that changed the plan

scope.md > Needs Verifying in 4-spec flagged one assumption that could force a redesign: which GPT Image model and endpoint accept reference images, and how many per request. The whole kernel rested on it.

Re-verified against OpenRouter on 2026-10-12, because the provider changed and the old answer was about the OpenAI API. The check was GET /api/v1/images/models, which returns each model’s capabilities as data — so this is read off the API, not off a docs page.

What came back good

  • Reference images work, with room to spare. openai/gpt-image-2.5-sunburst publishes input_references as a range of 0–16. Ink Desk sends exactly one, so the limit is never in play. scope.md > The Unique Kernel survives the provider change unchanged in substance.
  • quality carried over untouched. Same five paid names, same spelling — low, medium, high, xhigh, max. Nothing in the quality plan had to move.
  • One endpoint instead of two. The OpenAI API split /v1/images/generations from /v1/images/edits, with different content types. OpenRouter has a single POST /api/v1/images, and the only difference between a sheet and a panel is whether input_references is present. The kernel stops being a different endpoint and becomes one extra field.
  • Same model for both surfaces. The sheet is the reference the panels are judged against. A sheet drawn by one model and panels by another would differ in line weight even with the face held steady — the exact mismatch scope.md > What "Working" Looks Like is testing for. flare is generation-only, so it can't carry a reference at all.

The one thing that changed shape: size → aspect_ratio

There is no size parameter. The previous revision passed size: "1536x1024". This model through OpenRouter takes aspect_ratio: "3:2" instead — and because size is not in its passthrough list, it would have been dropped silently rather than rejected with a 400. That is the dangerous kind of breaking change: everything keeps working and quietly returns the wrong shape.

WasNowUsed for
1536×10243:2sheets, panels 1 and 4
1024×10241:1panels 2 and 3
1024×15362:3unused, as before

The mapping is exact, which is why this was a rewrite and not a redesign. The no-crop guarantee survives — it was always a claim about ratios matching slots, never about pixel counts. What is genuinely lost is control over resolution: the provider picks it. The kernel test now records the dimensions it actually receives, so that stops being unknown on day one.

gpt-image-1 still shuts down 2026-10-23, and gpt-image-1.5 on 2026-12-01. The “GPT Image model family” named in scope.md > Model Providers would have gone dark mid-hackathon, so both remain out. OpenRouter lists them; that does not make them safe to build on.

⚠ The model is no longer pinned — a real regression

The previous revision pinned the dated snapshot gpt-image-2.5-sunburst-2026-09-08 specifically so “an upstream revision cannot change the art style mid-build.” OpenRouter publishes no dated snapshot for this model. The alias is the only id available, so that protection is gone and cannot be recovered by configuration.

The risk is precise: the style shifting between the day a sheet is locked and the day the panels are drawn would look exactly like the kernel failing, while actually being the model moving underneath it. The one thing this project measures is the one thing the alias puts at risk.

Mitigations, given the build is days not months: the sheet is an image on disk rather than a prompt, so drift is damped by the kernel itself; re-run the kernel test before filming as a style canary, not just once at the start; regenerate both sheets if the style moves, since mixed-era art is worse than restyled art; and if it really bites, the escape hatch is calling OpenAI directly, where the snapshot still exists — a change to one file, which is what lib/image-provider.ts is named for.

Slice 1 now leads with a free probe

The capability check is the probe that would have caught the size change before a single image was paid for — which is exactly why it now runs first.

node scripts/kernel-test.mjs --probe-only [0a] model capabilities input_references · aspect_ratio · quality · free [0b] text model + structured output claude-sonnet-5-5 · ~free [0c] image model renders openai/gpt-image-2.5-sunburst · ~$0.008

Probe 0a asserts the model is listed, that input_references is in its supported_parameters, and that the configured ratios and quality are in their published enums — all without generating anything. The text probe sends no sampling parameters, so it would also catch that mistake — a non-default temperature, top_p or top_k is a 400 on this model family. Probe 0c prints usage.cost, the first real price this project has seen.

How this works, in plain language

Ink Desk is one Next.js app — a single program that serves the web page and answers requests from it. Nothing else has to be running.

Why this shape, and not something more elaborate

  • No database. One chapter of one story is a single JSON object. A database would add a service, a schema-migration story and a connection string, and prove nothing about the kernel.
  • No accounts. prd.md > States and Boundaries says one chapter at a time.
  • No separate backend. Next.js route handlers already run on the server — nothing extra to start on camera.
  • Images as plain files, on purpose. The hardest question in this build is “did the face actually hold?” The fastest way to answer it is to put sheet.png next to panel-1.png and look.

The kernel, mechanically

Every panel request is split in two. One half is frozen at lock and never rewritten; the other half is the only thing Claude authors per panel. That split is scope.md > The Unique Kernel.

Storyboard — four independent panels

Four pencil-sketch placeholders, then art arriving in whatever order it finishes, each playing the ink-in reveal as it lands. Per-panel independence is the governing rule: one panel's failure never touches another.

The page layout, fixed now

The framing goes in the prompt too, not just the request

So the model composes for the shape it is drawing:

  • Square close-up“Centre his face in frame with headroom above and below; keep his eyes on the upper third line and nothing important near the edges.”
  • Wide landscape“Place him off-centre in the left third, full body inside the frame with clear margin on every side.”

Ratios live in .env as IMAGE_SHEET_ASPECT, IMAGE_PANEL_ASPECT_WIDE and IMAGE_PANEL_ASPECT_SQUARE; the per-panel assignment sits in lib/prompts.ts beside the framing lines, so layout and framing stay together rather than drifting apart. Size panels in CSS from the ratio, not from hardcoded pixel numbers — those are no longer ours to set.

Components

Each one names the PRD heading it serves and the file it lives in. 5-build cites these.

Chapter Store lib/chapter.ts

The only code that reads or writes data/chapter.json. Every mutation goes through one update(). Two separate guarantees are needed, and they solve different problems.

1 · No torn files — temp file then rename

Write chapter.json.tmp, then rename() over the real file. Rename is atomic, so a crash mid-write can never leave a half-written chapter on disk.

2 · No lost updates — one in-process lock

This is the one that actually bites. With concurrency 2, two panels can finish milliseconds apart. Both update() calls read the same chapter, each applies its own panel, and the second write erases the first panel’s result. The art file is on disk, but the chapter no longer points at it — so a finished panel silently reverts to a pencil placeholder.

Atomic rename does not help here. Both writes are individually well-formed; they are just based on stale reads.

let lock = Promise.resolve() update(fn) { const run = async () => { const chapter = await read() // fresh read, inside the lock const next = fn(chapter) await writeAtomic(next) // tmp + rename return next } const result = lock.then(run, run) // then(run, run): a failure lock = result.catch(() => {}) doesn’t wedge the chain return result }

fn receives the chapter and returns the next one — callers must not close over a chapter they read earlier, or they reintroduce the stale read the lock exists to prevent.

Acceptance check — 5-build doesn’t call this done without it

  • Two panels completing at the same moment both survive in chapter.json: start two generations together, then assert both are done with distinct imageIds.
  • imageCount after four panels is 4, not fewer — a lost update shows up here too, which makes the header counter a free canary.

Serves prd.md > States and Boundaries. A single in-memory lock is sufficient because this is a local single-process app — one more thing deployment would have to rethink.

Panel Queue lib/queue.ts

An in-memory queue in the server process that runs at most 2 panel generations at once — resolving the concurrency call left open in the PRD. Each finished panel writes to chapter.json immediately, so the browser's poll sees panels appear independently and out of order.

Serves prd.md > Storyboard — The Main Studio, prd.md > Open Questions

Singletons & the Dev Server lib/singleton.ts

Three pieces of process state must be genuinely single or the guarantees above collapse: the panel queue, the update() lock, and serverRunId. Next.js re-evaluates module scope on every hot reload, which would quietly give you a second queue beside the first — 4 concurrent generations instead of 2 — and a second lock, bringing the lost-update bug straight back.

const g = globalThis as typeof globalThis & { __inkdesk?: InkDeskGlobals } export const singletons = (g.__inkdesk ??= { serverRunId: crypto.randomUUID(), // once per real process queue: createQueue(Number(process.env.PANEL_CONCURRENCY ?? 2)), chapterLock: Promise.resolve(), })

Pinning serverRunId here is also what keeps the restart fallback honest: it must change when the process restarts and not when a module reloads.

Every route handler declares the Node runtime

export const runtime = 'nodejs'

Without it a handler could be evaluated on the Edge runtime — no fs, no long-lived process — so disk writes and the in-memory queue both fail. Declaring it in all nine handlers is cheaper than debugging it once.

Background work outlives the response

POST /api/panels/start queues four jobs and responds immediately; the generations finish afterwards and write to chapter.json on their own. That is fine in a long-lived next dev process and is what makes “generation survives a reload” work at all. It is not fine on a serverless host, where the function may be frozen the moment the response is sent.

Deployment therefore needs rework for four independent reasons: the ephemeral filesystem, the missing image cap, background work after the response, and the single-process lock.

Derived Gates lib/gates.ts

One function, gates(chapter), returns which stations are unlocked. Computed from chapter state, never stored — storing them would let them drift out of sync with the thing they describe.

The same principle covers speech-bubble placement: a small lookup keyed on the panel's camera angle picks a corner, so Claude never has to return coordinates and there is nothing extra to get wrong.

Serves prd.md > Screens and Layout

Prompts lib/prompts.ts

Every prompt in one file, including the frozen style rules that are pasted into each panel request verbatim. Keeping them in one place is what makes “the frozen half never changes” checkable rather than aspirational.

Serves scope.md > The Unique Kernel, scope.md > Lettering

Schemas lib/schemas.ts

Four zod schemas — SynopsisSchema, CastSchema, DnaSchema, PageScriptSchema — passed to the Anthropic SDK's zodOutputFormat helper so the API constrains the response rather than being asked nicely for JSON.

Three things that are a 400 rather than a warning, worth knowing before writing them: every object needs additionalProperties: false; no recursive schemas and no min/max; and never send temperature, top_p or top_k — they are rejected outright on claude-sonnet-5-5 — re-verified against that exact model, not inherited. Prompt wording is the only steering lever.

Image Writer lib/images.ts

OpenRouter returns base64, never a URL. This decodes once, writes the file, and hands back only the id — which is why the browser only ever sees /api/image/<id> and never carries image bytes around.

Pick the extension from media_type, not from a hardcoded .png. Each response item carries its own media_type beside b64_json. This model should return image/png every time — but writing a JPEG’s bytes into a .png filename produces a file some viewers open, the <canvas> export may not, and nobody would think to suspect. One lookup removes a whole class of confusing bug for two lines. An unrecognised media_type is a hard failure rather than a guess.

Image Provider lib/image-provider.ts

One function, one endpoint, for both surfaces. A sheet is a call without input_references; a panel is the same call with one. Plain fetch — no SDK, because OpenRouter’s body is not the OpenAI images body and the openai package would not fit it even with a baseURL override.

This file is the provider seam, and it is named for that rather than for OpenRouter on purpose: it is the one file that changes if images ever move again — which is also the escape hatch if the unpinned alias restyles mid-build.

Reload mid-generation — and the floor underneath it

This is the one behavior that changed from the approved PRD; it's recorded in prd.md > Changes Since Approval.

Was

In-flight panels come back in the failed state with “Try again.” Four generations lost to a stray refresh.

Now

Generation continues server-side. A reload shows each panel finished or still inking — and it keeps going.

The floor exists because Next.js restarts the dev server on every code change and silently kills in-flight requests. Two conditions demote a stale inking panel to failed on read:

timeout startedAt older than GENERATION_TIMEOUT_MS server restart startedByRun !== serverRunId ↳ serverRunId is stamped once at boot, so every panel that was mid-flight is recognisably orphaned

So the original rule from the PRD is kept intact: nothing spins forever; nothing finished is lost.

Concurrency 2 was margin rather than necessity before and still is: it costs nothing, it keeps panels filling out of order, and it keeps a 429 off camera.

Where this will actually break

Behavior is specified in prd.md > States and Boundaries; this is the mapping. No raw error codes on screen, ever — provider errors go to the terminal in full, the browser gets a sentence.

What breaksWhat the user sees
429 or timeout on a panel One silent retry. If that fails too: “Panel 3 didn't come back, the studio is busy” + Try again. The other three are untouched.
402 — out of credits (balance at or below $1) The same “the studio is busy” sentence + Try again, because the PRD forbids raw error codes on screen. But this is the one failure that is not per-panel — it fails all four panels and both sheets alike, so the terminal is the only place the real cause appears, and it says so in full with the top-up link. Not retried — unlike a 429 it will not pass on its own.
The image model refuses a panel Rewrite panel — Claude rephrases only that panel's action, angle and background. Never the dialogue, never the DNA. A refusal is a wording problem, so it gets a different button than a timeout.
A redraw fails The previous version stays on screen and Ink & Publish stays open. A failed redraw never leaves a panel empty.
Dev server restarts mid-generation (every code change does this) Orphaned panels are caught by the startedByRun check and demoted to Try again on the next read.
Wrong model ID or key Every image call fails identically and confusingly — which is exactly why slice 1 is a single --probe-only call before any UI exists.
A request parameter is silently dropped (the new one, and the quietest) OpenRouter passes through only moderation, so an unsupported field like the old size is ignored rather than rejected: images come back the wrong shape with a 200 and no complaint. The capability probe in slice 1 exists for exactly this.
Claude names an unlocked or second character Rejected by the z.enum of locked ids at the API boundary, not discovered later as a broken page.

The useful unknown — does the lock actually hold?

Your stated learning goal is “how to keep character art consistent across AI-generated panels.” Verification settled the mechanism: input_references is supported up to 16, and face preservation is this model’s default behavior.

It cannot settle the result. Whether one sheet plus verbatim DNA actually holds a face across a close-up and a wide shot is not in any documentation. Only a generation can answer it.

Verified before anything else was changed

The instruction was to stop and report if reference images turned out to be unsupported. Via GET /api/v1/images/models:

  • input_references is supported, 0–16. Ink Desk needs 1. The kernel survives the provider change.
  • quality carried over unchanged. Same low/medium/high/xhigh/max.
  • size does not exist; aspect_ratio replaced it. Found by the probe rather than by a failed build.

What this cost, stated plainly

Three things got worse, and none of them were the reason for the change:

  1. The model is no longer pinnable — no dated snapshot exists on OpenRouter, so the protection against mid-build style drift is gone. Mitigated by re-running the kernel test; detailed in the warning in the verification section.
  2. Per-image cost is ~40% higher (a filming run goes ~$0.90 → ~$1.25) and the cost table dropped from published to estimated, because OpenRouter bills per token and publishes no per-tier token count. One kernel-test run fixes the second half of that.
  3. A new failure mode: 402 at $1. It fails every image at once rather than one panel, and the UI’s calm “studio is busy” message cannot say so — only the terminal can.

Two things got better: one endpoint instead of two with no multipart/form-data anywhere, so the kernel is a single field rather than a different request shape; and one dependency fewer, since the openai package is gone. And one open question closed: the OpenAI tier / IPM ceiling no longer applies.

Decisions and what’s still open

Decided

  • Images go through OpenRouter, not the OpenAI API. Your call, and a change after approval — recorded below. Tradeoffs accepted: no snapshot to pin to, ~40% higher per-image cost, a broker in the path. Bought: one account, one balance, and a provider seam that makes the next swap cheap.
  • Image model openai/gpt-image-2.5-sunburst — alias, not snapshot — for both surfaces. Forced by the gpt-image-1 shutdown and by OpenRouter publishing no dated snapshot. Tradeoff accepted: style drift is possible mid-build, mitigated by re-running the kernel test rather than by configuration. Also the slower of the two 2.5 tiers, which the placeholder states already cover.
  • Claude stays on the Anthropic API directly. Only images moved; routing text through a broker would buy nothing.
  • One endpoint for both surfaces — POST /api/v1/images, with input_references present for panels and absent for sheets. Simpler than the two-endpoint split it replaces.
  • aspect_ratio rather than size, because no size parameter exists. Forced by the provider. 3:2 and 1:1 replace 1536×1024 and 1024×1024 exactly, so the no-crop guarantee is unaffected; resolution is now the provider's choice.
  • Sheets at max, panels at high, both .env-configurable. Build at low, pay only when filming.
  • Text model claude-sonnet-5-5, pinned and .env-configurable. You caught that claude-sonnet-5 was superseded on 2026-09-28. Structured-output support and the sampling-parameter rejection were re-verified against the 5.5 family rather than inherited, and slice 1 now probes the text model too.
  • One 4-panel layout with fixed per-panel ratios — wide / two squares / wide, passed in each request and echoed as a framing line in each prompt, so a panel is never scaled into its slot. Sheet is landscape, because it’s a row of poses.
  • update() serialized through one lock; queue, lock and serverRunId on globalThis. You found the lost-update race: two panels finishing together would both read-modify-write, and the second write would silently revert the first to a placeholder. Route handlers declare runtime = 'nodejs'.
  • Next.js App Router, TypeScript, both keys in server route handlers. Tradeoff accepted: React rather than Angular, and the mockup's CSS is ported rather than reused.
  • Server-side disk storage. data/images/<id>.png + one data/chapter.json; the browser only ever sees /api/image/<id>. Tradeoff accepted: this is a local-only design, and a deployed version would need real object storage.
  • Generation survives a reload, with a timeout-and-restart floor. A change to the approved PRD, recorded there rather than edited in silently.
  • Local only; deployment stays in Later — and when revisited, it comes with a server-side image cap, because a public URL would otherwise expose the image budget.
  • Panel concurrency 2. Margin rather than necessity at Build-tier limits.
  • Structured JSON output with zod on all four text calls. An implementation detail derived from the above, not a product decision — it also turns the one-character-per-panel rule into something the API enforces.

Open — none of it blocks the build

  • The generation timeout value. Needs a real number; the kernel test measures it. Placeholder 180000 in .env.example.
  • The real per-image cost. The cost table is now an estimate rather than a published figure. One kernel-test run returns usage.cost and settles it.
  • The pixel dimensions returned at 3:2 and 1:1. Not ours to set any more. The kernel test records them; size panel CSS from the ratio until then.
  • Whether the alias restyles mid-build. Unanswerable in advance and unpreventable by configuration. Mitigation: re-run the kernel test before filming. Escape hatch: call OpenAI directly.
  • Your OpenAI tier. Closed by the provider change — the Build / Launch / Grow IPM ceilings no longer apply. Replaced by: keep the OpenRouter balance above ~$2.50 before filming, since 402 starts at $1.
  • The exact Next.js version. Whatever create-next-app@latest installs; nothing here depends on a specific major.
  • Carried from the PRD: page script as its own rail entry vs. a step inside Storyboard (drafted as a step); genre and tone chip sets (as the mockup has them); ink-in reveal timing in the reader (tune during build).
  • A server-side image cap — not built, since the app stays local-only. Becomes required if deployment is revisited.

Revision · 2026-10-13 · Ink Desk Studio (v2)

What changes, in plain language

Still one Next.js app. Three things grow: the desk becomes a shelf of projects (data/projects/<id>/project.json, the v1 file migrated once and left in place); the server gets two seams — storage (lib/store/: local files or MongoDB + bucket) and text provider (lib/llm.ts: Claude first, GPT Terra through OpenRouter when Claude cannot be used); and the page engine runs per page, addressed by project / chapter / page / panel, otherwise unchanged. The kernel is the same request, with the project's style rules in place of the one constant and, for an imported character, the uploaded bytes as the sheet.

Data model (v2)

Shapes — lib/types.ts, version: 2 
Project { id, title, stylePresetId, story { mode: 'pitch' | 'scenario', pitch, synopsis, scenario },
          library { characters[], assets[] }, chapters[], usage { images, costUsd },
          station, openPage, serverRunId, createdAt, updatedAt }
Asset   { id, kind: 'reference', name, blobId, mediaType, bytes, createdAt }
Character = v1 fields + source: 'drawn' | 'imported'
Chapter { id, title, plan: ChapterPlan | null, cover | null, pages[] }
Page    { index, layoutId: 'four-shot', panels[4] }          // the v1 Panel shape
ChapterPlan { pageCount, coverBrief, pages[{ panels: PanelLine[4] }] }

Migration (lib/migrate.ts): a version: 1 chapter → one project, one chapter, one page; image ids keep their names and the local blob store reads data/images/ as a fallback, so nothing moves. Queue keys become project:chapter:page:panel.

The two seams

Storage — lib/store/

listProjects · readProject · updateProject(id, fn) · createProject · putBlob · getBlob. local.ts: v1's chapter store generalized — one promise-chain lock per project on globalThis, temp-then-rename. cloud.ts: mongodb with a rev counter and findOneAndUpdate (re-read and retry on a mismatch, bounded); blobs on an S3-compatible bucket with @aws-sdk/client-s3 (S3, R2, MinIO), still served through /api/blob/<id>. Selected by INKDESK_STORAGE=local|cloud. The queue stays in-process in both modes; the stale-inking floor is unchanged; deployment stays Later.

Text — lib/llm.ts and the Terra fallback

One ask(schema, prompt, maxTokens, { images? }). Primary: the v1 Anthropic call, with image content blocks for the DNA-from-picture. Fallback: OpenRouter POST /api/v1/chat/completions, response_format: { type: 'json_schema', json_schema: { name, strict: true, schema: z.toJSONSchema(schema) } }, provider.require_parameters: true, reply validated with the same zod schema. Fires on a missing key, a 402, or a 5xx/529/429 past the single retry; LLM_FALLBACK=auto|always|never, LLM_FALLBACK_MODEL (default openai/gpt-5.6-terra). The terminal names the provider on every call.

Image models, style presets, candidate locks

lib/image-models.ts builds each request body from the model's published parameter list, so an unsupported parameter is refused before the request leaves — v1's silent size drop, generalized. Verified: openai/gpt-image-2.5-sunburst (the only candidate with quality; references ≤ 16). Candidates, in the app only after kernel-test --model passes before Oct 18: google/gemini-nano-banana-2.1, bytedance-seed/seedream-5-0-*, black-forest-labs/flux-3-image, recraft/recraft-v4-styles.

lib/styles.ts: manga-bw (today's rules; right-to-left, paged) and manhwa-colour (full colour, clean digital line, cel shading, vertical) — frozen rules text per project, never naming a real work. A style reference image or a setting reference image rides as input_references[1] beside the sheet; kernel-test --style-ref / --setting-ref draw one sheet and three panels at medium (≈ $0.10) and decide whether the docs may call it a lock.

Assets, the Director, routing, reader

  • Uploads: POST /api/projects/[id]/assets via request.formData(); PNG/JPEG/WebP ≤ 8 MB; GET /api/blob/[id] for every blob. Import reference sets the sheet, source: 'imported', and Claude (or the fallback) writes the DNA from the picture; Lock applies the v1 rule.
  • The Director: chapterPlanSchema(lockedIds, pageCount) — a tuple of v1 page-script shapes, alternation per slot; page count 3–6; scenarios past ~12 000 characters are condensed first. lib/cost.ts estimates the chapter from measured low and estimated high figures, before anything is generated. Routes: plan, pages/[n]/start, pages/[n]/panels/[i], /rewrite, cover (lead character's sheet only — two references only after a kernel test).
  • Routing: app/page.tsx → dashboard; app/p/[projectId]/page.tsx → the studio; app/api/projects/…. Prerequisite: read node_modules/next/dist/docs/ (Next 16.4 has breaking changes — params, server/client boundaries) before any routing code.
  • Reader and export: cover first, then pages, direction from the preset; PDF with pdf-lib in the browser — each page through the existing drawPage onto a canvas, embedded as PNG at page size. Chosen over print CSS: same file on every browser, bubbles included.

The demo video pipeline — video/
